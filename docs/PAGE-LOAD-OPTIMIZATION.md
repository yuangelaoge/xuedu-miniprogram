# 页面加载优化（2026-09-27）

## 范围与状态

用户确认将首页之外的页面加载也做精简，并完成代码提交、推送；真机计时由用户进行。本次为源码改动与本地验证，尚未部署云函数或上传微信前端，不改变数据库结构。

## 当前实现

原页面会依次请求启动身份、学期列表和页面业务资料，部分页面还读取整周数据生成少量概览。现在通过 `bootstrap.payload.page` 一次取得当前页面需要的资料，固定页面形状和服务端权限，复用原分页查询；协议详见 [V2-PROTOCOL.md](V2-PROTOCOL.md)。

| 页面 | 精简方式 |
| --- | --- |
| 听课安排 | 只读取所选学期、周次的任务和计划，不带记录、课程实例或无课时间 |
| 无课时间 | 只读本人目标周填报，保留历史学期深链和未保存编辑 |
| 听课记录 | 一页记录加数据库计数，不再读取整周记录两次；统计与导出仍按需独立读取 |
| 我的 | 按 ID 读取本人班级；待审核数量直接计数，不逐页加载班级与申请 |
| 管理、课程总表 | 合并首次列表和必要选项；翻页不重复查询学期列表、班级及概览 |
| 记录详情、填写 | 合并身份、学期与目标记录或任务；照片仍单独取得受控地址 |

通常首次加载各一次云函数调用，记录详情为两次。冷启动直达且保存了本人历史学期时可能多一次恢复查询；表单选项、统计、照片和导出不计入这一启动次数。首页沿用已发布的合并启动实现。

服务端继续使用可信微信上下文，成员只读本人任务与记录。身份变化清除受限内容，响应前仍核对权限版本和业务轮次；翻页拒绝旧轮次，导出继续核对报表版本。未增加哈希校验。旧后端不支持页面合并字段时，客户端回退原查询路径。

## 验证范围

- 自动化覆盖启动请求次数、分页追加、数据库读取范围、待审总数、历史学期、旧后端回退、维护和未入组状态、越权与读取中权限变化、清空后旧轮次、审核体验角色隔离。
- 全量本地测试 177 项：168 项通过、9 项数据库集成测试因未启用对应环境而跳过；类型检查、17 个 WXML 模板编译与云函数构建通过，未操作线上数据。
- 尚无本次改动的真机速度证据；请求次数减少不等于固定耗时或“提升 90%”。
