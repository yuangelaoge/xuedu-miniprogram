# 读取容量与历史隔离检查（2026-10-23）

本页记录当前工作区的稳定性改动与本地证据，不代表这些改动已经部署。测试全部使用一次性本地 PostgreSQL 17 与合成身份、课程、记录；未连接生产、未下载照片。

## 已确认的问题与修复范围

1. 012 已限制快速排班页只读取有效任务及当前草稿，但旧 `query/week`、首页及排班页的后备路径仍读取废弃草稿历史；若仅在内存过滤，读取版本清单和数据库往返依然增长。本轮服务端改为按状态及当前草稿归属查询，保留历史数据。
2. 按“每页 50 条”不足以控制响应体积。记录允许六个文字字段各 5,000 字符；独立边界探针将 35 条合成记录的文字字段取到合法上限，每条 `data` 为 90,271 字节（低于数据库 131,072 字节限制），旧快速记录页实际返回 **3,162,927 字节**，超过已观察到的 1,048,576 字节平台限制。013 为通用查询增加 **384 KiB 整条实体分页预算**，返回真实末条 ID 作为下一页游标，不裁剪文字或遗漏记录。
3. 旧排班计算 RPC 虽有 4,996 行及 8 MB 保护，却把重复生成的废弃任务一并计入；达到保护线后会无法继续计算。013 仅预读正式、已提交、待调整、草稿任务及有效计划，保留取消草稿、原任务和幂等回执；不再读取 `superseded` / `cancelled` 历史。
4. Excel 汇总的班级快照过去逐班查询；本轮采用最多 100 个 ID 一批，继续逐行核对并登记版本，保留尚未提交的本次改动。

## 路径清单

| 入口 | 读取范围与容量约束 | 需要保留的边界 |
| --- | --- | --- |
| 快速首页 | 组织当前学期、当前周、本人有效任务及记录链接，管理统计为计数 | 不能沿用听课安排页选择的历史周；不拉照片内容 |
| 快速听课安排 | 指定学期/周、有效任务及当前草稿；普通干事/信息部干事仅本人任务；管理员额外取得当周有效课程实例 | 任务课程备选与班级人数快照完整；课程实例仍有 5,000 条上限 |
| 记录列表、课程、班级、管理列表、记录版本 | 默认最多 50 条、请求最多 100 条，并受 384 KiB 整实体预算限制；继续使用游标 | 任何非空游标必须继续读取，不能把首屏当完整名单；权限仍由服务端判定 |
| 个人页、本人无课时间 | 本人、选定学期/周，申请数使用计数 | 不得读取其他人的具体无课时间 |
| 后备首页/排班页、旧 `week` 查询 | 有效任务和当前草稿，历史状态在数据库查询阶段排除；首页只带本人任务及记录链接，`week` 的记录仅保留归属/跳转/班级标签 | 上周无课时间复制和页面统计不再附带整周文字正文；仍验证实际身份和权限 |
| 提交状态、汇总统计 | 指定学期/周；任务及计划只读有效状态，记录内部按游标取全；对外输出状态或汇总 | 不把“未提交”当零；导出期间版本变动必须重做 |
| 排班计算与安排表导出 RPC | 当前周所需实体；轮换只看上一周记录；保留 4,996 行 / 8 MB 内部保护 | 回执先于可变状态判断；任务取消、待调整、已完成保护不变 |
| 照片/记录提交预读 | 本人绑定、目标任务、选中备选、当前记录、最多 3 个历史兼容照片引用、幂等回执 | 照片文件不进入 JSON 页面；本测试不证明相机或真实上传成功 |
| 单记录、单任务、照片链接 | 明确对象 ID；照片链接最多 30 个并逐项鉴权 | 不把查询提示的身份当可信身份，不输出私有照片正文 |
| Excel / 名单导出 | 同一学期/周、同一版本，记录分批读取后在客户端合并 | 每批核对权限与版本；不能因分页改变原始文字、统计或图表 |

## 合成容量回归

运行：`node scripts/v2-db-test.mjs --capacity`。发布检查应同时运行所有数据库与业务回归。

夹具包含 35 名成员、四种角色、18 周、每个任务 5 门备选课、630 份记录、3,150 个课程实例；每周再存入 25 次废弃重生成，共 15,750 条历史任务。额外检查一周累计 100 次重生成，以及 35 份六字段各 5,000 中文字符的合法记录。

响应大小按 `{ok:true,data:响应}` 的实际 UTF-8 JSON 计算，代表场景要求低于 **768 KiB**，给平台限制预留至少 25% 空间。历史加入前后的响应字节数及数据库调用次数必须相同；同时验证四种身份、当前/下一周、历史学期、完整课程备选、分页不重不漏与文字不截断。

代表场景实测（最终发布以同一测试的当次输出为准）：

| 路径 | 响应字节数 |
| --- | ---: |
| 管理员快速首页 | 4,719 |
| 管理员快速排班页（正式及草稿各 35 任务） | 329,366 |
| 管理员快速记录页 | 37,370 |
| 信息部干事快速排班页 | 7,960 |
| 普通干事快速排班页 | 7,937 |
| 后备首页 | 6,667 |

同期单周被排除的历史 JSON 为 **2,953,100 字节**。累计 100 次重生成后，历史达到 **11,814,500 字节**，排班计算 RPC 的必要读集为 **423,262 字节**，安排表 RPC 为 **224,179 字节**，仍保留取消草稿及待调整任务。

六字段各 5,000 个中文字符的 35 份记录，在快速页面四角色、后备页面及通用列表查询中均用 **9 页完整返回**，单次最大 **365,168 字节**；每个文字字段逐条比对，未截断。管理员及信息部干事的 Excel / 名单分页导出同样完整返回 35 份记录，最大 **442,169 字节**；版本变化时停止，组部长及普通干事不能借新参数获得导出权限。旧客户端的大结果返回明确 `RESPONSE_TOO_LARGE` 错误，正常大小的旧导出继续兼容。

Excel 汇总班级读取改为批量后，该合成场景数据库调用数由 **48 次降至 14 次**。013 重复执行前后，任务、计划、记录的完整内容指纹不变；两项 RPC 仍仅允许 `service_role` 调用。

最终统一检查中，本机 20 次暖读平均 SQL 时间：首页约 3.05 ms、排班页约 35.73 ms；这是数据库本地计算时间，不含网络、云函数冷启动和手机绘制，不能当作线上响应承诺。完整通过证据与发布状态见 [稳定性检查](STABILITY-2026-10-23.md)。

## 验证边界

- 该容量样本代表 35 人、18 周、每任务 5 个备选，不能据此承诺任意人数、5,000 个课程实例、100 个备选及所有字段同时达到上限仍在单包范围内。聚合接口仍需整体响应预算与后续分批设计。
- 384 KiB 是单列表预算；组合页面可能包含多个列表和快照。服务端增加 **900 KiB 整体只读响应保护**，超限返回明确可诊断错误；这项保护不能代替列表分页或把超限数据伪装成空数据。单条数据保留完整，不能为过检查默默裁剪。
- 本轮本地回归不替代 Android/iPhone、双微信身份、真实上传、完整线上一周以及备份恢复验收。未配置线上告警，也未产生自动付费或部署。
- 实际发布仍须确认部署版本、数据库迁移版本和前端上传来源；现有截图、构建成功或本地测试不能替代这些证据。
