# 课表导入超时修复（2026-09-30，本地源码）

手机确认导入时，云函数在平台实际 3 秒执行上限内超时（`-504003`）。原路径为每门新课程重建全部课程实例，并为每个日期反复读取版本、例外和班级；整份文件还超过旧单批 700 日期限制。

现在客户端先让服务端对完整 JSON 做只读预检，预检通过后才提示确认。确认后自动分批，每批最多 6 门课程、60 个上课日期、40 个新增班级。每批独立事务提交；导入页面显示进度。发出首批前，本机保存原文、轮次、学期、成员、权限版本及各批固定请求号。请求成功但手机未收到响应时，继续操作会用相同请求号重放，服务端幂等回执防止重复写入；续传不会用已部分导入的全文重新预检。若权限、轮次或同 ID 资料发生冲突，则停止并提示核对，不跳过课程。清除本机续传记录不会删除已成功写入的批次。

服务端对新课程直接生成对应上课日期实例，保留现有课程维护时的版本重建逻辑。每批只读取当前班级、当前学期课程、参与班级和必需的权限/幂等资料；日期循环不再查询数据库。班级和课程稳定 ID 仍按原文件保存，合班不拆分。

本地只读核对用户提供的单份 TXT：32 个合班组、154 门课程、1431 个日期；完整格式校验无错误，规划为 30 批，合计数量一致。新“25自动化3/4班”与云端已有的独立“25自动化3班”使用不同 ID。文件未包含周日补充课程，当前学期保持 5 个上课日；本修复不变更学期设置。

本地类型检查、自动化测试、17 个 WXML 编译和云函数构建通过。自动化测试覆盖完整预检权限、重复 ID 拒绝、154 门课程分批无遗漏、实例快照、查询次数不随日期增加，以及首批提交成功但响应丢失后的续传。独立 Docker PostgreSQL 测试因本机 Docker daemon 未运行而未执行；本地结果不能证明手机和云端每批一定能在 3 秒内完成。

尚未部署云函数、上传小程序或发起线上导入。后续若经用户明确授权执行，先部署兼容旧协议的服务端，再上传客户端；保留现有函数名、环境和实际 3 秒上限，核对两项执行上限配置与平台一致。随后用手机选取原 TXT，只确认一次导入，观察 30 批进度；若中断，返回同一账号和学期的导入页继续。完成后分别核对新增班级、课程与上课日期数量，特别检查独立班和合班。任何部分失败先核对成功批次，不直接重导整份文件。
