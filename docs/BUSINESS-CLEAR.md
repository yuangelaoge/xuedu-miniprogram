# 换届清空业务数据：开发交付

## 用户确认的用途

用“清空业务数据（保留管理员）”替换管理工作台原“试用结束后清理”入口。由管理员在换届时手动执行，不按自然年、学年或日期筛选，也不定时执行：删除当前工作区保存的全部历年业务资料，为下一轮使用重新配置。

| 保留 | 清除 |
| --- | --- |
| 所有管理员的成员 ID、姓名、学号、微信绑定、角色和原有启停状态；停用管理员不会复活 | 组部长、普通成员（含归档成员）、所有入组申请 |
| 代码中的组织名称、程序、云环境、密钥、初始化资格等系统配置 | 所有学期及其年级、班级、课表、无课时间、正式排班、草稿和听课记录 |
| 本次清空的一条最少操作记录、任务完成标识和新数据轮次 | 历史操作记录、业务请求去重记录、照片登记信息、当前环境阶段目录内的照片（含未登记照片） |

管理员的旧班级引用清为空，避免保留已经删除的年度班级配置。管理员登录和管理权限不变；建立新学期、导入真实班级和课程后，在管理工作台选择本人真实班级，才可报名听课。此补充入口只允许当前管理员为自己补齐空班级，不是任意换班／修改他人档案入口。

不删除平台备份、平台日志、手机原图、其他设备草稿或导出副本。当前执行设备仅移除同一环境、同一模式的表单缓存；其他设备旧轮次请求被服务器拒绝。

## 入口和使用流程

我的 → 管理工作台 → 操作记录 → 查看业务数据清空范围。

1. 后端校验当前微信对应的有效管理员身份，返回实际目标阶段、保留管理员数以及将删除的成员／申请／学期／班级／课程／记录／已登记照片数量；同时探测照片目录是否支持完整核查。
2. 对话框说明全部清除范围，必须输入 `清空业务数据，保留管理员`。取消或输入不符不开始任务。
3. 后端校验 epoch/version，冻结业务写入。等待在途请求结束，逐批扫描当前 stage 目录并删除照片。
4. 目录再次核查为空后，以事务替换为空白业务状态和保留的管理员，更新 epoch。页面进入新学期设置；从首页等页面重进也会引导到管理工作台。
5. 中断后再次预览、确认并继续同一任务。不能手工取消冻结伪装完成。最后一次响应丢失时，同任务重试不会再次清空。

支持 trial 和 production，但始终由后端固定 stage 决定目标；客户端不能传 stage 切换。demo 不显示入口。不支持目录核查的旧文档存储后端会拒绝该能力。

## 源码与接口

- 管理工作台：`miniprogram/pages/manage/manage.ts`、`manage.wxml`。
- 协议常量和预览类型：`miniprogram/domain/business-clear.ts`。
- 云端操作：`businessClearPreview`、`businessClearBegin`、`businessClearStep`。
- JSONB 文档可选字段：`businessClear`（任务及执行租约）、`lastBusinessClearId`（最后完成标识）。沿用既有 `cleaning`、epoch、version 和 CAS。
- 保留管理员规则：`server/policy.ts` 的 `clearBusiness`。
- 重建支持：`member-page.ts` 的空学期引导、管理页空状态、`restoreAdminClass` 命令、无班级报名／排班拦截。

旧 `cleanupPreview/cleanup` 后端操作暂保留原有试用清理语义，供旧客户端兼容，**没有把旧“清空试用数据”的确认扩大成删除课表**；新版页面已不调用它们。原 `resetAll*` 仍是独立的试用彻底重置，会删除管理员，仅初始化微信可执行。三种任务互斥，不允许混跑。

## 数据库迁移、发布与回退

本次不改变 SQL 表、RPC、RLS、照片桶或密钥，**无需新增或重跑 SQL 迁移**。新字段为现有 JSONB 文档内的可选任务元数据，只有管理员实际开始清空才写入；部署／构建本身不清空数据。

交给部署与运维负责人执行前核对：

- 先发布兼容旧操作的后端，再更新小程序。执行清空前，所有管理员应更新到支持空学期的新客户端；旧客户端可能不能显示空学期。
- 本版沿用已知试用函数 3 秒执行上限，10 秒排空等待及任务租约。**目标函数执行上限必须不超过 3 秒**；正式环境还未验收，不可未经核对按其他执行时长启用。提高超时须先联动重新设计／调整排空与租约、测试，再发布，不能只改控制台。测试用受控时钟覆盖超时续跑，不代表线上超时已验收。
- 照片 SDK 的 stage 目录列举、删除结果和超时行为必须在目标环境验收。范围只在当前环境 `xuedu-photos/<stage>/`，不包含另一阶段、其他桶或其他环境。
- 实际清空前先确认需要留存的业务和照片已有经验证可恢复的备份。照片删除不可由代码回退恢复；清理失败期间保持冻结并排查后继续。
- 从未开始新清空任务时可按既有流程评估源码回退。清空已经开始或完成后，禁止直接回退到不认识 `businessClear`、空学期和空管理员班级的旧后端／客户端；应以本版修复续跑，或由运维按独立授权恢复已验证的数据与照片备份。

本任务未部署、未上传小程序、未执行线上迁移、未修改线上配置、未执行真实清空或重置。
