## 当前实现与使用方式

- 云端协议为 `protocolVersion: 2`，启动信息、分页列表、学期、目标周、记录详情和报表分别查询。独立实体表与事务 RPC 替代旧 workspace 大 JSON；旧 `snapshot`、V1 写入、旧清理和删除全部管理员的重置接口被拒绝。
- 管理员可限时开启“自动通过新申请”，必须设置截止时间，服务端到期即视为关闭；只创建普通成员，保留可信身份、重复/学号校验及操作审计。工作台提供自动通过人员分页核查；已有待审核申请仍需人工审核，关闭不移除已通过人员，业务清空后不沿用设置。详见 [自动通过说明](docs/AUTO-APPROVAL.md)。
- 管理员平权任免、本人卸任、普通成员恢复、新微信申请并由管理员核实换绑；数据库事务保护至少一名有效管理员。权限变更要求二次确认与原因。
- 班级独立建立/维护，学期单独选参与班级；课程按生效日留版本，停/调/补课按具体日期生成实例。未完成任务调整先形成草稿，人工确认后生效；已完成任务和记录快照保留。
- 查看历史学期是账号/环境范围的本机状态；新学期先为草稿，独立“启用学期”才改变全组当前学期。
- 本人记录在服务器首次提交时间起严格小于24小时可修改；管理员可超时纠错。原因、并发版本、历史版本及照片引用保留；统计和新导出使用最新版本。
- 唯一业务清空保留**全部管理员及绑定班级，原启停状态不变**。确认文字为“清空业务数据，保留管理员及其班级”。先预览、冻结、固定旧轮次、分批续跑，成功后换轮次；没有删除全部管理员的入口。
- 空库仅指定初始化微信可一次事务创建真实班级、学期和首位管理员；不注入示例。清空后原管理员直接建立学期/课程，无需重新登记。示例资料仅限 demo。

打开项目时保持 AppID，不修改线上环境。当前本地 cloud 配置指向已切换的既有 V2 环境。真实联调保持只读，不随手修改业务资料。离线开发可使用 demo；不要通过运行旧 `scripts/cloud-smoke.mjs` 验证 V2，该脚本仍是 V1 历史联调工具。

# 学风督察小程序

微信原生 TypeScript + Sass 的学风督察小程序。四个底部入口：首页、听课安排、听课记录、我的；成员、组部长、管理员流程已经连接，可在微信开发者工具中运行。

**当前本地源码为 trial；已有真实微信身份、PostgreSQL 快照读取、本人管理员注册和班级修正的验证记录，照片和多人验收仍未完成。** 试用私有表、照片桶及 `xueduTrial` 云函数已部署；除本人真实班级外，环境仍含明确标注的示例班级和课程。最近上传记录为微信开发版 1.0，未设置体验版、提交审核或正式发布，不代表已开放多人试用。`demo` 模式仍可供开发测试，该模式的数据和签字照片仅保存在当前设备。

源码仓库：[yuangelaoge/xuedu-miniprogram](https://github.com/yuangelaoge/xuedu-miniprogram)，已确认 PRIVATE，项目为闭源内部使用，未授予开源许可证。依赖原有许可证不受影响；密钥、本机私有配置、测试导出和依赖目录不入库。

多人试用接入、首位管理员设置、试用清理和正式环境切换见 [云端部署说明](docs/CLOUD-SETUP.md)。下方演示身份切换仅适用于手动配置为 demo 的本机测试，不适用于当前 trial。

## 运行

1. 在微信开发者工具中打开本项目根目录，保持现有 AppID。小程序目录已配置为 `miniprogram/`。
2. 点击“编译”。开发者工具使用现有 TypeScript 和 Sass 编译插件；小程序无运行时 npm 依赖，无需执行“构建 npm”。
3. 当前 trial 使用登录微信的真实身份；未审核账号进入申请页。当前首位管理员已登记；新环境的首位管理员须先按部署说明配置 `BOOTSTRAP_OPENID`，再本人填写真实资料，勿重复初始化现有管理员；班级不存在时不要随意选择示例班级。
4. 如需本地演示，先将 `miniprogram/config/runtime.ts` 的 mode 改为 demo 再编译：示例成员为林知夏，“我的 → 开发体验”可切换角色或体验入组申请。演示切换不授予云端权限；不要上传未核对模式的版本。

进行源码验证：

```sh
npm ci
npm run typecheck
npm test
```

类型检查启用了 `skipLibCheck`，跳过旧版微信声明文件自身的泛型兼容问题，应用源码仍采用严格类型检查。

## 建议体验顺序

1. 普通成员：查看本周正式任务，修改下周无课时间并保存。
2. 组部长：打开“听课安排”，默认查看下周；生成草稿、重新生成、确认排班。
3. 管理员：进入无课时间页，开启“第 X 周我也听课”，选时间并保存。回到安排页重生成草稿时纳入候选。
4. 管理员：对假期周点击“跳过本周”，填写原因。跳过后仍可重新生成，但需要再次确认。
5. 普通成员：打开已到听课日期的个人任务，填写人数和名单，上传清晰的签字照片，保存草稿或提交。
6. 管理人员：在“听课记录”查看记录和周统计，导出名单 TXT、Excel，或复制名单。Excel 含原始数据、全部班级及各年级统计页和可编辑图表。
7. 管理员：在“我的 → 管理工作台 → 学期与年级”建立新学期，选择参与年级，按实际情况导入新年级专业班级与课程；切换回旧学期仍可查看原记录。

### 精简后的入口

- 课程查询：听课安排 → 课程总表，不再单独占底部栏。
- 填写记录：首页个人任务卡 → 去填写；取消顶部重复提交卡。
- 管理功能：我的 → 管理工作台；入口显示待审核数，进入后按权限切换成员、课表、学期、操作记录。
- 听课记录：成员默认看个人记录，管理人员默认看全组；不再在“我的”重复放置入口。
- 开发演示：身份切换和入组体验统一放在开发体验页，上线前必须移除。

## 已实现的业务边界

- 成员名单导入已取消。成员管理仅有“待审核”和“现有成员”；管理员和组部长可单个／批量通过、驳回申请（需原因），可删除普通组员。申请通过后仅开通普通成员；管理员可授予或撤销组部长身份。
- 申请中的姓名、学号、班级需本人填写；重复申请不重复建人，重复学号不能认领或覆盖已有账号。未通过审核的体验身份、被移除身份访问业务页会回到申请页。
- 删除组员采用归档：取消访问与排班资格，未完成任务移入原方案的 `cancelledTasks`，列出待处理班级，旧草稿作废；已完成任务、原记录和照片保留，不物理删除。被移除身份暂不能自行重新申请，需要管理员核实；换绑／恢复入口尚未接入。
- 本班及包含本班的合班不能安排；每名成员每周至多一次；整个任务的连续节次都必须可用。
- 最大流保证教学班匹配数量，最小费用依次优化班级轮换、成员轮换。重生成可能得到相同最优方案。
- 每周分别保存正式方案与待确认草稿；重新生成不直接覆盖正式任务，每个新版本必须重新确认。
- 若无课时间在生成后变化，确认时重新校验。已有正式任务时不能通过修改无课时间静默取消任务。
- 有提交记录的周暂不允许重排或跳过，避免丢失历史凭证。暂不支持已提交记录的修改、补交审核或记录撤回流程。
- 管理员默认免排，报名按周保存；组部长暂采用同样的可选参加入口。
- 普通成员可看全组汇总条目，但暂只看自己的明细和照片；管理员与组部长可以查看明细和导出。生产权限范围仍需业务方确认。
- `-1` 为缺失，`0` 为真实零。缺失值不会进入人数或比例运算；分母为零时不输出虚假比例。
- 违纪暂沿用模板的“睡觉 + 玩手机 + 说话”行为人次，不声称是去重人数。年级整体出勤率采用有效记录对应人次的加权结果。
- 照片上限暂定 3 张。demo 照片及云端提交前的草稿照片保存在本机；trial/production 提交时经云函数上传到私有存储并绑定记录。清理应用数据、卸载或设备损坏可能使本地文件丢失；真实照片上传／受控读取及备份恢复仍待线上验收。

## 导入格式

课表支持 UTF-8 JSON 文件或粘贴 JSON，包含可选的 `classes` 以及 `courses`。有“解析预览 → 错误检查 → 确认导入”，重复 ID 和非法班级引用会阻止整批写入。仅管理员可用，夹带 `members` 字段会明确拒绝，旧成员导入接口已移除。

- [课程示例](examples/courses.json)：追加新课程及班级，可有多个时段和有效周次。省略 `semesterId` 时归属当前学期。
- 一个行政班若出现在不同的交叉合班组合中，当前排班器会明确报错；需要业务方确定行政班／教学班覆盖口径后再扩展算法。
- 真实教务 Excel 课表的文件格式尚未提供，目前不支持直接解析任意 XLSX 课表。项目中的两份 Office 文件是**输出参考模板**，不是课表导入样本。

## 结构

```text
miniprogram/
  domain/       纯业务逻辑：排班、权限检查、记录、导入、统计、OOXML 导出
  services/     本地存储、视图映射、微信文件保存与打开
  pages/        四个主页面及课程、无课时间、提交、详情、管理、申请、开发体验页
  assets/       本地底部导航图标
references/     用户提供的原始模板与截图
examples/       受支持的 JSON 交换格式
tests/          业务回归与排班穷举比对
scripts/        图标生成与开发者工具烟雾测试
```

`services/store.ts` 是存储边界，`services/cloud.ts` 是云函数调用适配，`server/gateway.ts` 执行可信微信身份、权限、事务业务和数据脱敏，构建至两个独立云函数。云端模式拒绝本地任意 `transact` 与演示身份切换，照片先上传并登记归属，再绑定提交记录。试用环境及函数已部署；正式环境尚未部署。

demo 本地存储主键为 `xuedu.demo.v1`，旧数据缺少 `applications` 时自动补为空数组，不重置已有记录；demo 表单草稿键为 `xuedu.form.<成员ID>.<任务ID>`，云端模式为 `xuedu.form.<环境ID>.<模式>.<轮次>.<成员ID>.<任务ID>`，草稿均不跨设备同步。demo 申请身份键为 `xuedu.demo.applicant`，不是 OpenID，不能迁移成真实微信绑定。导出文件保存在微信的 `USER_DATA_PATH`，支持系统允许的打开／分享；模拟器无法分享时，可在真机使用文件菜单，TXT 还可直接复制。
