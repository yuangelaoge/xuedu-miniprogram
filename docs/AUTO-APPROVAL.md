**状态更新（2026-09-23）**：功能随 V2 已部署，003、004 迁移已执行。下方“尚未部署”及迁移交付文字是实施前记录，不是当前待执行步骤。2026-09-23 16:25 的只读页面记录显示开关已开启；有效状态以服务端当前时间和实时设置为准。参见 [V2 部署记录](DEPLOYMENT-2026-09-23-V2.md)。

本功能为 V2 本地源码交付，尚未部署或执行线上迁移。原 AppID、环境和函数名不变。

## 使用规则

管理员进入“管理工作台 → 入组申请”，打开“自动通过新申请”，填写截止日期和时刻后保存。页面按北京时间输入、显示，服务端保存带时区的时间。未设置、无效或不晚于服务器当前时间的截止时间不能开启。管理员可以提前关闭或修改截止时间，其他角色不能操作。

服务端在每次申请时判断有效期；恰好达到截止时间就视为关闭，无需定时任务，也不依赖管理员页面保持打开。设置记录开启/关闭者与服务器时间；操作记录保存前后设置。到期是预定规则生效，不伪造一次管理员手动关闭操作。

新用户仍填写姓名、学号、班级，身份只取微信可信上下文。有效期内校验通过后，一次事务建立普通成员、微信绑定、已通过申请和审计，随后进入首页。不能自选管理员或部长。已占用学号、重复申请、已有绑定及已取消资格不能借此绕过原校验。已有待审核申请不会被批量自动批准，仍由管理人员处理；被驳回的申请可修改后重新提交。

关闭或到期只影响后续申请，不移除已加入成员。管理员在“自动通过人员”分页查看姓名、学号、申请时班级和通过时间，必要时到成员管理核查处理。业务清空后设置恢复关闭，历史自动通过申请按业务清空规则删除。

## 事务与并发

开启/关闭需要当前 workspace 的 expectedVersion；与其他修改冲突时刷新重试。申请事务核对最新设置、工作区与权限版本、身份和学号唯一性；数据库用自己的时钟再次校验截止时间，不能靠客户端时间延长窗口。网关判断有效但提交时已到期时整笔回滚，提示重新提交转人工审核；不留下半个成员或申请。

幂等结果沿用 epoch + 可信身份 + requestId。已自动通过的同请求重试不会重复建人。自动创建事务仅允许普通有效成员及其对应的四项变更；数据库拒绝夹带权限提升或其他对象修改。

## 迁移交付说明（由独立部署任务执行）

新增 `server/migrations/004-auto-approval.sql`，必须在 003 V2 结构之后、启用本版后端之前执行。首次从 V1 切换仍遵循 V2-CUTOVER 的冻结、保留清单、恢复材料、prepare、核对、open 流程，不能单独在 V1 库执行 004。已是 V2 的库由部署任务安排写入维护窗口和结构核对。

004 在私有 workspace 增加有界配置列 auto_approval，在 applications 增加分页索引，替换读取/提交 RPC 并新增私有校验函数。新列默认为 NULL（关闭），不改成员、申请或历史记录；不需要回填，不删除数据。RPC 继续仅服务端调用，表权限不开放。脚本包在单个事务中，可重复应用；失败回滚。部署前应核对现有结构与 003 一致，不能用 IF NOT EXISTS 掩盖其他结构差异。

核对新增列、索引与函数定义/权限，并确认默认关闭、管理员开启/关闭、截止边界和普通成员创建，再开放业务。仅回退页面或代码不会移除已经加入的成员；保留审计，不把回退说成撤销业务。没有提供自动执行线上 SQL 的脚本或后台定时任务。
