# 首页任务空白排查与本地兼容性修复

用户反馈新版首页出现任务卡片，但课程、班级、时间、地点、教师均为空，只显示“待完成”和“查看安排”；至少两人反馈。此次授权仅本地修复，未上传、部署或修改线上数据。

## 证据与判断

- 首页先筛选有效任务，再用 `homeTask()` 生成显示字段。即便课程快照缺失，`timeLabel` 仍包含固定连接文字；截图连该文字也没有，不能仅用“课程数据为空”解释。
- 近期新增下周任务时，将卡片抽成循环中的 `include`，内部隐式依赖外层 `item`。隐式循环作用域是排查重点，尚未证实是手机故障根因。
- **修改前**，本机 WXML 编译器和微信开发者工具均能用完整合成任务显示全部字段，未复现手机故障。未获得故障设备实际包、渲染日志或该成员线上任务读回结果。
- “全部安排”跳转不携带首页周次，安排页首次默认下周。跨页看不到仍需在同一学期、同一周核对；此项未在本次修改。

## 本地修改

- `cloud-home.wxml` 导入命名模板，本周、下周循环分别显式传入 `task`。
- `cloud-home-task.wxml` 全部字段和按钮使用显式 `task`，人数列表也在该模板作用域内渲染，不再嵌套依赖外部 `item` 的 include。
- 查询、权限、任务状态与排班数据均未改变。照片大小报错是另一问题，本次未修改照片流程。

## 已实际验证

- `npm run typecheck`、`npm run test:wxml` 通过。
- `node --import tsx --test tests/v2-home-render.test.ts tests/v2-course-options-ui.test.ts`：8 通过、0 跳过、0 失败。
- 新增测试编译实际 index → cloud → home 模板，核对本周/下周的课程、班级、时间、地点、教师、多人课程人数、零与缺失人数、按钮目标 ID、已提交/待调整状态，以及刷新后顺序变化。
- 修改后在开发者工具注入本周/下周合成任务，实际读取渲染文字，完整字段及 60 人/0 人均显示；验证结束恢复页面数据。没有提交合成任务或调用线上写接口。

这是待真机确认的兼容性修复，不是已复现根因或已修复线上故障的结论。后续发布后应由原故障设备核对字段与填写入口；若同周安排页仍无任务，继续检查该成员绑定、任务状态及查询响应，不重新生成或清空真实安排来掩盖问题。
