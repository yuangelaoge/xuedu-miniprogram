# 本地发布检查

本轮新增的检查入口只使用本地合成资料及临时 PostgreSQL，不连接生产环境，不上传微信、不部署，也不修改真实业务资料。它可以提前发现已覆盖的回归，不能代替 Android/iPhone 真机验收或线上配置核对。

## 使用

在项目根目录运行：

```sh
npm run check:release
```

依次执行前后端类型检查、所有非数据库测试、完整 PostgreSQL 测试、真实 WXML 编译与云函数构建。数据库检查使用本机已经存在的 `postgres:17` Docker 镜像，自动建立并删除临时容器；不下载镜像、不安装依赖。Docker、镜像、依赖或微信 WXML 编译器缺失时直接失败。`WECHAT_WCC` 可指定已经安装的编译器。

所有 PostgreSQL 场景都按顺序应用 `server/migrations/003-*.sql` 及后续迁移，包含审核沙盒、信息部权限、课程备选、任务范围修复和按字节限制分页。不同测试文件之间重建临时数据库，避免迁移重放及种子数据互相污染。数据库测试未运行、跳过或失败，都不能得到通过结果；非数据库测试出现跳过也会阻止发布检查通过。

结果和日志写入被 Git 忽略的 `artifacts/release-check/<时间>-<进程号>/`。`manifest.json` 记录源码提交、源码与构建产物 SHA-256、各项结果和用时；不保存源码内容、凭证、个人资料或环境变量。工作区中的相关未提交代码同样计入校验，不以提交号代替实际文件状态。

## 防止“测过的不是传上去的”

检查期间相关源码一旦改变，本次检查失败。准备上传/部署时，对目标工作区再次运行：

```sh
npm run check:release:verify -- artifacts/release-check/<时间>-<进程号>/manifest.json
```

它核对当前源码和云函数构建是否仍与完整通过的结果一致；不同则必须重新检查。实际发布应使用该工作区或其完整副本，发布操作仍需授权，并在完成后独立读回版本与云端配置。清单不会自动证明微信平台上传包、线上 SDK、权限或超时配置与本地一致。

## 当前覆盖

| 场景 | 自动检查范围 |
| --- | --- |
| 基础事务与权限 | 私有表/RPC、身份变更、版本冲突、幂等、最后一名管理员、跨学期分页 |
| 六类页面 | 页面数据形状、角色范围、分页、历史数据隔离、重复草稿隔离 |
| 排班 | 约束、备选课程、确认/补排/跳过、并发和响应回执体积 |
| 记录与照片 | 旧协议兼容、提交/修改重试、照片登记失败、24 小时限制；文件传输用本地模拟 |
| 完整业务链 | 保存无课→信息部生成草稿→管理员确认→文件照片登记→选择备选课程提交→丢响应重试→修改→Excel 导出及版本复核；PG 验证新分页协议 |
| 长期数据容量 | 35 人、多周数据、重复生成草稿后的页面与相关查询体积、数据库耗时 |
| 分页导出 | 新旧 Excel/TXT 等价、65 条跨页完整性、35 份合法长备注、途中变更/权限撤销拒绝、空周 |
| 前端与图表 | 本周/下周渲染、字段与人数、表单和请求异常、Excel 图表结构与颜色口径 |

可按需单独运行 `npm run test:db:all`，或 `node scripts/v2-db-test.mjs --pages` / `--scheduling` / `--records` / `--options` / `--page-scope` / `--capacity` / `--flow`。单项通过不能冒充完整发布检查通过。

真机仍需确认：两种系统实际照片传输与压缩、网络中断后的操作、多设备刷新、正式包来源，以及至少一遍真实授权业务流程。本地性能数字不等于云端耗时；本地检查通过也不表示这轮代码已经发布。
