已接续主分支 `01e6981`，解决与最新界面修复在页面生命周期上的冲突，保留无课时间退出提醒和管理按钮修复。本节取代下方“进一步精简”的上线方案。上一轮并行化仍有 9 次数据库往返；新增 `006-page-bootstrap.sql`，将六类页面的当前身份、学期、页面资料和统计放在同一个数据库事务内读取。前端发送 `fastPage: true` 才启用新返回结构。

| 页面 | 新路径 |
| --- | --- |
| 首页 | 当前学期、本人的有效任务/记录链接、本人填报、周计划及按角色汇总的三个数字 |

以上页面均为 **1 次云函数调用、1 次数据库 RPC**；首页从前一版 9 次数据库请求减为 1 次，减少约 89%。首次进入保存了历史学期的页面时，恢复该选择仍可能多一次请求。管理、填写、记录详情和照片继续走原路径；照片仍按记录授权。

### 鉴权和兼容

- 云函数先校验可信微信上下文及 AppID，数据库只按该身份联查当前绑定和有效成员，拒绝客户端声明的身份/角色。新 RPC 仅授予 `service_role`，内部再次自检角色，私有表不开放客户端访问。
- 所有 V2 写入会独占锁定 workspace 行。新读取事务持有共享锁，使核验身份与页面读取之间不能插入撤权/清空；遇到正在写入直接返回版本冲突，避免等待耗尽 3 秒。无需再次通过网络核对权限版本。写入、照片和旧路径原有校验继续有效。
- 首页只下载本人任务及记录链接，三个概览数字由数据库汇总，不再为管理人员的计数下载整周观察表、名单和照片字段。记录详情按需加载。
- 新前端兼容旧云函数；新云函数发现缺失 006 的 RPC 时回退旧读取路径，仅缓存“函数不存在”。权限拒绝、数据库错误或锁冲突不能触发回退。若先部署函数再执行迁移，须重新启动/部署云函数实例以退出缺失缓存，因此推荐迁移优先。
- 保留下面已实现的 15 秒主页面内存复用和旧路径读取提示。`data.readPath: "single-rpc"` 用于验证实际走到了新路径；`resourceVersions.workspace` 为该事务工作区版本，各实体自己的 version 继续用于修改校验。

## 历史：2026-09-30 进一步精简（单次 RPC 前的方案）

基于 `f3f21d1`，继续减少数据库等待和重复进入页面的请求；不改数据库结构，不调整平台 3 秒上限。

- 四个主页面加载成功后，15 秒内自动返回页面直接保留本机内存中的内容，不再次调用云函数。下拉刷新、点击重试、切换学期和保存后刷新仍即时请求。写入发出、服务端拒绝请求、已观察到的数据版本/身份/权限变化都会让旧页面失效；审核体验模式不复用。其他设备刚做的变化可能等到下次刷新才显示，用户可随时下拉刷新。
- 客户端带上最近已知的成员和学期 ID 作为 `readHint`。服务器先读取权限版本，再并行读取当前微信绑定、提示的成员、所需学期；提示不提供角色或授权。成员必须与数据库中当前微信绑定一致，否则回到实际绑定成员读取。响应前仍核对权限版本和轮次，写入和照片权限保持服务端校验。没有跨请求缓存服务端身份。
- 已审核成员启动时不再查询本人申请；未入组成员仍读取申请。首页不再读取、分页或传输整周课程实例；任务、记录、无课时间和统计口径保留，普通成员的任务从数据库查询起就限定本人。维护期间首页不读取业务周数据。

在合成数据各资源一页的情况下：首页数据库请求从 11 次降至 9 次；再次读取时的顺序等待从 7 轮降至 4 轮，首次读取为 5 轮。课程实例越多，省去的分页越多。15 秒内直接返回已加载主页面为 0 次请求。以上是代码路径和本地测试结果，不是线上耗时承诺，不能据此保证所有调用都少于 3 秒。

## 当前实现

原页面会依次请求启动身份、学期列表和页面业务资料，部分页面还读取整周数据生成少量概览。现在通过 `bootstrap.payload.page` 一次取得当前页面需要的资料，固定页面形状和服务端权限，复用原分页查询；协议详见 [V2-PROTOCOL.md](V2-PROTOCOL.md)。

| 页面 | 精简方式 |
| --- | --- |
| 听课安排 | 只读取所选学期、周次的任务和计划，不带记录、课程实例或无课时间 |
| 无课时间 | 只读本人目标周填报，保留历史学期深链和未保存编辑 |
| 听课记录 | 一页记录加数据库计数，不再读取整周记录两次；统计与导出仍按需独立读取 |
| 我的 | 按 ID 读取本人班级；待审核数量直接计数，不逐页加载班级与申请 |
| 管理、课程总表 | 合并首次列表和必要选项；翻页不重复查询学期列表、班级及概览 |
| 记录详情、填写 | 合并身份、学期与目标记录或任务；照片仍单独取得受控地址 |

通常首次加载各一次云函数调用，记录详情为两次。冷启动直达且保存了本人历史学期时可能多一次恢复查询；表单选项、统计、照片和导出不计入这一启动次数。首页沿用已发布的合并启动实现。

服务端继续使用可信微信上下文，成员只读本人任务与记录。身份变化清除受限内容，响应前仍核对权限版本和业务轮次；翻页拒绝旧轮次，导出继续核对报表版本。未增加哈希校验。旧后端不支持页面合并字段时，客户端回退原查询路径。
