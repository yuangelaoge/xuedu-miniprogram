# V2 架构与维护边界（本地源码，未部署）

本轮遵循已确认长期运行计划 1/2/4/5/6/7。沿用微信原生小程序、云函数和 PostgreSQL；业务模式统一 cloud，demo 独立用于开发，历史 trial 环境名不产生新的环境或权限含义。

## 当前分层

- `miniprogram/domain/v2/protocol.ts` 定义协议、资源和版本；旧领域排班/统计逻辑在有界上下文复用。
- `server/v2/gateway.ts` 负责可信身份、业务权限、记录24小时窗口、课程日期实例、任务草稿及清空；服务器时间不可由客户端伪造。
- `server/v2/repository.ts`、`postgres.ts` 与003 SQL负责独立行查询、分页、原子提交；workspace只存配置/轮次/维护状态，不再容纳业务历史数组。
- 每个 members/bindings/applications/classes/semesters/semester_classes/courses/course_versions/occurrences/exceptions/availability/plans/tasks/records/record_versions/photos/audit/requests/maintenance/rebindings 资源单独表。实体的有界 JSON字段不替代无限增长的数组；图片只存私有桶，表内为引用和归属。
- 提交事务核对轮次、维护状态、权限版本、操作者绑定、读/写版本及唯一约束；至少一名有效管理员由数据库保护。幂等独立按轮次+身份+请求ID保存，超过500条不丢去重依据。
- `miniprogram/services/v2/` 按启动/学期/周/分页资源读取，云端不使用旧 snapshot。`viewSemesterId` 按账号和环境留本机，与组织 `activeSemesterId` 分开；历史任务/记录使用自己的 semesterId。
- 入口只打包V2三模块。旧 `server/gateway.ts`、`policy.ts`、`postgres.ts` 为V1历史回归资料，不能直接作为当前云入口，旧彻底重置没有可调用路径。

## 管理、纠错与历史

管理员可任免其他有效成员为管理员、卸任为普通成员；最后一名有效管理员不能被撤销、停用或卸任。成员恢复复用ID，不恢复取消的任务。新微信只能申请换绑，由管理员线下核实并二次确认；旧微信绑定在同一事务撤销，不能自行认领身份或恢复管理员权限。仅剩管理员失联时属于平台维护者受控恢复任务，本轮没有对普通用户开放旁路。

班级可无课表独立建立、改名、调专业和停用；引用班级不物理删除。学期草稿与启用分开。课程版本按生效日期，停/调/补课按具体日期生成实例；影响未完成正式任务时标待调整并生成草稿，管理人员确认后替换。已有记录的周允许只调整剩余任务，已完成任务计入每人每周一次。

记录首次提交时间由服务器保存，成员只可在不足24小时修改本人观察数据/名单/备注/照片，达到24小时由管理员纠错。修改原因、版本及历史照片均保留，不改变任务、提交人、课程和首次时间。组部长不因此获得修改他人记录权限。报表取最新记录版本及当时班级/课程快照，导出版本变化需重做；旧文件不会自动更新。

## 业务清空与首次初始化

只有新的业务清空：保留全部管理员（包括停用管理员）和去重后的绑定班级完整资料，原启停状态不变；保留系统连接配置和最少当前维护/审计。其他成员、申请、学期、课程、无课时间、排班、记录版本和照片等业务资料删除。保留班级不保留其历史课程/学期。

预览分别显示管理员、保留班级、删除班级；精确确认文字为“清空业务数据，保留管理员及其班级”，旧文字无效。维护任务固定旧轮次目录 `cloud/<oldEpoch>/`，冻结业务，排空后分批删照片/数据；失败保持冻结、等待租约后续跑。目录越界停止，延迟旧任务不得删除新轮次；执行上限通过两份明确配置校验，不能隐含固定3秒。旧清理任务未完成时拒绝切换，不能跳过其冻结状态。

首次空库仅指定初始化微信能一次事务建立真实班级、学期和管理员；并发只能建一次。无管理员/无启用学期/无课程分别引导，云端没有示例注入。清空后原管理员及班级绑定仍存在，从管理工作台重建学期和课程，无需重新注册；删除全部管理员的彻底重置功能已撤除。

[V2-CUTOVER.md](V2-CUTOVER.md) 定义离线计划、服务端prepare、独立完整导出核对和open；[V2-PROTOCOL.md](V2-PROTOCOL.md) 记录实际接口。必须先完成核对才清旧数据。恢复副本不入库、访问受控；旧照片可能跨多个历史轮次，须冻结后完整核查并固定清单。开始破坏性步骤后优先修复续跑，不切回不认识新表的版本。代码回退或JSON副本都不能恢复已删图片；完整备份与告警不在本轮。

本地阶段已验证关键领域边界、入口、离线切换及真实本地PG事务；不把本地通过说成线上已部署、权限/相机/照片/双设备已验收或多年保障已完成。最终测试与页面编译数量以本轮交付记录为准。未进行线上清空、部署、上传、迁移或配置修改。

# 架构与日常运维（2026-09-22）

## 当前结论

已基本前后端分层，尚未完全平台无关。小程序只向云函数发业务命令，不能直接读写私有数据库／照片，最终身份、权限和校验在服务端。前端与后端可以分别部署；业务规则源码仍共用 `miniprogram/domain`，后端打包时引用它。修改公共规则或接口时要判断是否同时更新两端。

| 层 | 当前源码 | 职责及耦合 |
| --- | --- | --- |
| 页面 | miniprogram/pages | 微信原生页面与交互 |
| 客户端服务 | miniprogram/services/cloud.ts、store.ts | demo/trial 分流、命令、缓存、快照；cloud.ts 使用 wx.cloud.callFunction |
| 公共业务规则 | miniprogram/domain | 排班、统计、导入、角色等纯逻辑；目前放在小程序目录，并非独立 shared 包 |
| 服务端网关 | server/gateway.ts、policy.ts | 可信身份、鉴权、事务、幂等、数据脱敏 |
| 云平台入口 | cloudfunctions/xueduTrial/index.js | wx-server-sdk 身份上下文、环境变量与平台 SDK |
| 数据适配 | server/postgres.ts、server/migrations | PostgreSQL JSONB + CAS、私有照片桶；保留文档数据库分支 |

数据库仍是单工作区聚合 JSON，不是已完成多年数据拆表方案。迁移云厂商可复用主要业务规则，但要替换微信身份验证、调用方式、存储适配与运维配置，不是改一个 URL 就完成。

## 分别部署

1. 前端：先核对 `miniprogram/config/runtime.ts` 的模式、环境 ID、函数名；类型检查和测试后，用微信开发者工具编译、预览／真机测试、上传开发版本。设置体验版与正式提交审核／发布是后续独立动作。最近记录已上传开发版 1.0，未设置体验版、提交审核或正式发布；详见 README 的发布记录。
2. 后端：修改 server／公共 domain 后，先运行 `npm run typecheck && npm test && npm run build:cloud`，再只部署目标环境的目标云函数（微信工具“上传并部署：云端安装依赖”或官方 CLI）。不要直接改 generated 文件。
3. 数据库：只有结构、RPC、权限等变更才执行相应 `server/migrations/*.sql`；不是每次前后端上传都重建数据库。服务端 Key、管理员允许标识仅留在函数环境配置，不写入前端或仓库。
4. 改页面通常只需前端上传；改后端实现且接口兼容可只更新函数；改共享协议／规则常需两端。先部署兼容旧客户端的后端，再更新前端，防止旧版本仍在使用时中断。
5. 正式版应使用另一个环境与 xueduProduction。当前已验收的是试用的部分链路，不能把构建好的 production 当作已部署。

## 附件及基础资料导入

目前 references 保存两份汇总模板和七张旧系统截图。Word 用于请假／旷课名单结构，Excel 用于统计字段、缺失值、公式和图表，截图用于流程和页面参考。它们不是教务原始课表，不足以验证直接 Excel 课表导入。

- 小程序 → 我的 → 管理工作台 → 学期：建立新学期，设置第一周周一、年级（例如 25,26,27）、教学周数和节次等。当前不是任意编辑既有学期的完整配置管理器。
- 工作台 → 课表：选择 JSON/TXT 或粘贴 JSON，解析预览后确认。可随课程导入新增班级；既有班级用原 ID 引用，不能重复声明。当前要求至少一条课程，不能只上传班级清单。重复课程 ID 拒绝，不是覆盖更新。
- 云端模式确认后会提交内容给服务端再次校验并保存；不再显示旧的“不会上传服务器”提示。
- 还没有独立网页管理后台、通用教务 XLSX 自动识别、纯班级手工维护页面或完整课表版本变更界面。现阶段对技术人员可用，但对部长日常维护还不够方便。
- 后端管理也应经过相同受鉴权命令（createSemester/import）。不建议手工修改 PostgreSQL workspace 的 JSON，否则会绕过校验、审计和并发保护。

## 第二位管理员

当前支持多个 admin 的数据模型，但成员管理只开放 member/leader 切换，不能通过现有界面增加第二位管理员。BOOTSTRAP_OPENID 只在无任何管理员时初始化第一位，改成另一个人的标识不会自动新增管理员。

后续可新增：对方真实微信申请并审核入组 → 现有管理员明确确认“授予管理员” → 服务端检查并记录审计；撤销／交接应保证至少一个有效管理员。小程序业务管理员不需要获得腾讯云密钥或微信公众平台账号。本轮没有实现或执行此授权扩展。

## 彻底重置（新增，试用环境）

入口：我的 → 管理工作台 → 操作记录 → 查看彻底重置范围。与原“试用数据清理”是两个独立功能。

- 删除范围：全部成员和管理员、申请、学期、班级、课程、无课时间、排班／草稿、记录、操作记录、已登记照片，以及 xuedu-photos 桶 trial/ 目录中的未登记照片。清空后保存空白工作区和最少系统元数据，不 DROP 数据库或删除云环境。
- 保留：代码、云环境、连接密钥、BOOTSTRAP_OPENID 指定的本人重新初始化资格。平台备份／日志、设备上的照片／缓存／导出文件、他人保存的副本不由该功能远程清除；成功操作会清掉当前设备对应试用环境的表单缓存。
- 权限：仅当前有效管理员且可信微信匹配 BOOTSTRAP_OPENID 可执行；production 硬性拒绝，不支持完整存储核查的旧后端也拒绝。
- 流程：只读预览、输入“清空全部业务数据”、冻结写入、等待在途上传、每次最多扫描／删除 20 个照片、确认目录为空后清空业务。异常不宣称完成，保持冻结，重新预览并继续即可。未知路径或清单格式异常会停止，而不是冒险删除。
- 当前等待在途上传 10 秒，依据已部署函数最大执行时长 3 秒。将来提高函数超时必须同步调整排空机制，不能只改控制台超时。
- 成功后更换数据轮次，旧客户端写入拒绝；仅允许原指定微信在申请页建立真实空白学期和本人班级，随后本人填写资料重新初始化管理员，不恢复演示课表。正式课表仍需导入。

本轮 58 项测试、类型检查、两套构建及修改页面 WXML 编译通过；真实试用云函数已部署。只读预览与照片目录核查通过，确认弹窗已取消，未调用 resetAllBegin/resetAllStep，未删除真实数据。真实照片删除、失败恢复和重置后的真机初始化仍未破坏性演练。

## 新版换届清空入口（源码交付，尚未部署）

用户最新要求把原试用清理入口替换为“清空业务数据（保留管理员）”：不按日期过滤，删除全部年度业务配置及资料，包括部长、成员、年级、班级、课表和照片，保留管理员身份与系统配置。独立于上文会删除管理员的彻底重置。新清空适用当前环境的 trial/production，需明确输入确认，分批处理、失败冻结可续跑；完成后管理员从管理工作台重建学期和课表。
