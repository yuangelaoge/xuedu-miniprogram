## 三种模式

| 模式 | 身份与数据 | 用途 |
| --- | --- | --- |
| demo | 当前设备虚构数据，可切换演示角色 | 开发演示 |
| trial | 微信 OPENID、试用云环境、`xueduTrial`；PG 表 `xuedu_private.workspace` 的 trial 行 | 邀请少量成员测试 |
| production | 另一个云环境、`xueduProduction`；采用 PG 时使用该环境表中的 production 行，尚未部署 | 正式使用 |

试用和正式须配置不同云环境。服务端阶段固定在两个函数构建入口中；PG 按 stage 读写工作区，旧 document 适配才使用 `xuedu_trial_workspace`／`xuedu_production_workspace` 集合。客户端传 `stage`、`actorId`、`role` 无法切换环境或取得权限；客户端也验证服务端阶段。申请通过后与该小程序下的微信 OPENID 关联，不是手机号、微信昵称或可转让的密码。

云端数据不从旧的 `xuedu.demo.v1` 迁移，也不把本地角色当微信账号。试用环境只初始化虚构课程配置，不带演示人员和任务；正式环境不带虚构班级、课程或成员。

## 接入前准备

以下用于新环境接入；当前试用环境已完成基础接入，不应重复创建或重放迁移。PG 使用 `server/migrations/` 中的表、RPC 和私有桶定义，并配置服务端 Key；迁移须先核对目标环境与已执行状态。

1. 确认云开发已开通，取得环境 ID，并确认与项目现有 AppID 关联。不需要把 AppSecret、云密钥或登录票据放进仓库。
2. 使用专门的试用环境，不在已有生产环境里测试。开通或升级收费套餐另行确认，不由脚本自动购买。
3. **仅旧 document 适配**：创建集合 `xuedu_trial_workspace`，配置 `cloudfunctions/database.rules.json`。当前 PG 使用私有表、RPC 角色校验与 RLS，不执行此集合初始化步骤。
4. **仅旧 document 适配**：使用 `cloudfunctions/storage.rules.json`。当前 PG 使用私有 `xuedu-photos` 桶及相应数据库权限，不套用该 JSON 规则。**不要修改其他项目共用存储桶的规则**，应使用独立环境。
5. 执行 `npm run typecheck && npm test && npm run build:cloud`。构建生成的 JS 不进 Git，换电脑须重新构建。使用现有锁定依赖即可，不需要前端构建 npm。
6. 微信工具中仅对 `cloudfunctions/xueduTrial` 执行“上传并部署：云端安装依赖”。云函数使用 Node.js 18 或兼容的更新运行时；配置超时需覆盖照片处理和事务。此步骤需真实环境与部署权限。
7. 在 `miniprogram/config/runtime.ts` 填写 `mode: "trial"`、试用 `env` 和 `functionName: "xueduTrial"`。连接失败会提示错误，不会退回示例身份。

## 同步、照片和当前限制

- 页面打开和下拉刷新时从云端更新，操作成功后使用服务端返回的新数据；目前不是实时推送。
- 客户端只发送明确业务命令，不上传整份本地状态覆盖云端；审核、成员、无课时间、排班、提交、课表和学期变更在服务端再次校验。
- 当前 PG 通过读取、内存计算及 revision/CAS 提交更新聚合状态，明确冲突时重试，避免并发覆盖；旧 document 适配使用数据库事务。最近 500 个请求标识用于网络重放去重。业务命令提交接近 650KB JSON 字节时拒绝继续写入，不截断历史。**适用于当前少量成员试用，不是已验收的多年大规模存储方案**，正式上线前应拆分存储、分页和制定归档策略。
- 照片由受鉴权云函数上传，绑定本人任务，不接受其他人或其他任务的 fileID。每张约 500KB 内、每份记录 1–3 张，每任务至多 12 次上传以限制异常重复。大图会先尝试压缩，仍过大时需裁剪，并人工核对签字清晰度。
- 正式记录的照片通过服务端鉴权获取短时链接（当前设 300 秒），非公开永久地址；拥有链接的人在有效期内可能访问，请勿公开转发。
- 云端全量明细只返回管理人员；普通成员只拿自己姓名名单和照片，其他人的条目去除名单、照片及反馈，保留已允许展示的汇总字段。未审核成员只拿本人申请及申请所需班级配置。
- 填写草稿及上传前照片仍在本机，**不跨设备同步草稿**；提交成功的记录及照片进入云端。草稿键含环境、模式、清理轮次和成员，旧试用草稿不会在正式版或新轮次恢复。
- 暂无孤儿文件定时回收；极端超时可能使照片上传完成但未登记，需按环境存储目录核查。正式删除试用环境前需一并检查存储目录，不把删除业务记录等同于删除所有文件。

## 试用结束与正式上线

新增“彻底重置全部业务数据”与下述原清理功能分开：原清理保留管理员与课表，彻底重置连全部管理员、学期、班级、课程一起清空，仍保留指定微信重新初始化资格。范围、恢复流程、分批清理及无法删除的副本边界见 [架构与运维](ARCHITECTURE-OPERATIONS.md)。已部署试用后端、58 项测试通过，只做过线上只读预览，未执行真实清空。

本轮没有执行任何试用数据清理。日后清理入口：管理员 → 管理工作台 → 操作记录 → 查看试用数据清理范围。

1. 先查看成员、申请、记录和照片数量；需要留存的测试结果先另行导出。
2. 输入精确确认文字 `清空试用数据` 才执行。删除试用成员（含组部长）、所有申请、无课时间、排班、记录、已登记云端照片；保留在任管理员、学期和基础课表配置。
3. 清理期间冻结试用写入；照片删除失败保留清单，管理员重新进入仍可查看范围并重试，不能宣称已经清理完成。
4. 成功后更换数据轮次，旧手机缓存请求不能重新写回已清理数据。正式函数硬性拒绝此操作。
5. 用户手机上保存的原图、导出文件和本地填写草稿无法通过云端远程删除；需要测试者自行清理小程序缓存和自行保存的副本。
6. 正式版使用另一个环境，按选定适配配置数据库、存储权限及管理员允许标识（PG 使用迁移、RPC/RLS 与私有桶；旧 document 适配使用集合及 JSON 规则），按真实数据配置班级和学期，再开通真实成员。若正式环境尚无班级，须由部署管理员先配置班级，不能用演示班级假装真实资料。
7. 正式发布前移除演示页面打包入口，完成服务端权限、照片、真实课表、多人并发和备份恢复验收，再单独授权提交审核、发布。试用成员不会自动获得正式权限。

## 必做联调

- 两个真实微信账号：A 提交申请，B 看见并审核，A 下拉刷新进入；第三个待审核账号不能访问内部数据。
- 通过后的成员关闭重进，身份保持；另一台设备使用同一微信后可读到本人云端记录。
- 两人同时审核同一申请只生效一次；普通成员和组部长越权操作被服务端拒绝。
- 成员提交无课时间，管理人员刷新后能生成并确认排班；不能听本班、不能每周两次。
- 签字照片上传后，管理人员在另一台手机能打开；别人的普通成员账号不能换 ID 读取。
- 专用试用数据演练清理失败重试、旧轮次拒绝写入、生产函数拒绝清理。演练会删除试用资料，执行前单独确认。
