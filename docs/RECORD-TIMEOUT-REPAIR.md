## 纯后端重试兼容

最终交付按用户最新要求只改后端。`27f15f2` 中的前端待确认按钮、本机恢复模块及新增恢复协议已通过后续补偿提交撤除；最终 `miniprogram/` 与 `3c3fbe1` 完全一致，版本和配置未变。不需要上传新小程序。

旧客户端每次重试会生成新 requestId。对于照片、recordSubmit、recordEdit，服务端对操作、学期、预期版本及完整 payload 生成规范化 SHA-256，使用内部 `record-v1-<digest>-p<permissionsVersion>` 请求键。回执继续由原事务按可信微信与轮次隔离；客户端不能使用此保留前缀。其他命令沿用原请求编号。

- 内容与预期版本相同、权限版本未变化时，新编号重试返回实际已提交的成功结果，不重复上传、登记或增加历史版本。对象字段顺序变化不影响匹配。
- 内容或预期版本变化视为新写入，仍须通过版本及任务唯一约束。权限变化后重新鉴权与业务校验，不能重放原特权结果；已取消资格或换绑的微信拒绝访问。
- 未提交成功就没有成功回执；重试正常重新执行。没有查询不到即判定未保存的逻辑。
- 删除 `resolveWrite`、`writeState`、`writeDigest` 对外协议以及无业务修改的终止回执。结果格式保持旧客户端所需的 changed、refresh、photoId/fileID；不会向旧客户端返回“终止但成功”的结果。

该兼容只保证相同请求内容的重试。重选照片导致压缩字节改变、重新打开表单导致预期版本或内容变化，不能视作同一请求。旧页面的本机草稿能力保持原样，无法由后端补出退出页面后的本机照片恢复功能；手机仍可能先显示网络失败，需要重试或刷新核对。

## 照片对象

路径由服务端对轮次、可信身份、任务和照片内容计算 SHA-256，使用 `cloud/<epoch>/stable-<hash>.jpg`。同一内容重试使用同一路径；只有这个受控路径允许覆盖相同字节，内容或所有者变化会生成不同路径。旧 UUID 路径禁止覆盖，历史照片不删除、不改变内容。

存储成功而登记失败仍可能留下一份未登记对象；本次不自动清理。重试同一图片复用该对象路径。权限版本变化后可能重新登记同一物理对象，但不重复存储相同内容。存储调用使用本地替身，真实私有桶上传及覆盖行为尚未实测。
