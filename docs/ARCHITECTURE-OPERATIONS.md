# 架构与日常运维（2026-09-22）

## 当前结论

已基本前后端分层，尚未完全平台无关。小程序只向云函数发业务命令，不能直接读写私有数据库／照片，最终身份、权限和校验在服务端。前端与后端可以分别部署；业务规则源码仍共用 `miniprogram/domain`，后端打包时引用它。修改公共规则或接口时要判断是否同时更新两端。

| 层 | 当前源码 | 职责及耦合 |
| --- | --- | --- |
| 页面 | miniprogram/pages | 微信原生页面与交互 |
| 客户端服务 | miniprogram/services/cloud.ts、store.ts | demo/trial 分流、命令、缓存、快照；cloud.ts 使用 wx.cloud.callFunction |
| 公共业务规则 | miniprogram/domain | 排班、统计、导入、角色等纯逻辑；目前放在小程序目录，并非独立 shared 包 |
| 服务端网关 | server/gateway.ts、policy.ts | 可信身份、鉴权、事务、幂等、数据脱敏 |
| 云平台入口 | cloudfunctions/xueduTrial/index.js | wx-server-sdk 身份上下文、环境变量与平台 SDK |
| 数据适配 | server/postgres.ts、server/migrations | PostgreSQL JSONB + CAS、私有照片桶；保留文档数据库分支 |

数据库仍是单工作区聚合 JSON，不是已完成多年数据拆表方案。迁移云厂商可复用主要业务规则，但要替换微信身份验证、调用方式、存储适配与运维配置，不是改一个 URL 就完成。

## 分别部署

1. 前端：先核对 `miniprogram/config/runtime.ts` 的模式、环境 ID、函数名；类型检查和测试后，用微信开发者工具编译、预览／真机测试、上传开发版本。设置体验版与正式提交审核／发布是后续独立动作。本轮未重新上传小程序。
2. 后端：修改 server／公共 domain 后，先运行 `npm run typecheck && npm test && npm run build:cloud`，再只部署目标环境的目标云函数（微信工具“上传并部署：云端安装依赖”或官方 CLI）。不要直接改 generated 文件。
3. 数据库：只有结构、RPC、权限等变更才执行相应 `server/migrations/*.sql`；不是每次前后端上传都重建数据库。服务端 Key、管理员允许标识仅留在函数环境配置，不写入前端或仓库。
4. 改页面通常只需前端上传；改后端实现且接口兼容可只更新函数；改共享协议／规则常需两端。先部署兼容旧客户端的后端，再更新前端，防止旧版本仍在使用时中断。
5. 正式版应使用另一个环境与 xueduProduction。当前已验收的是试用的部分链路，不能把构建好的 production 当作已部署。

## 附件及基础资料导入

目前 references 保存两份汇总模板和七张旧系统截图。Word 用于请假／旷课名单结构，Excel 用于统计字段、缺失值、公式和图表，截图用于流程和页面参考。它们不是教务原始课表，不足以验证直接 Excel 课表导入。

- 小程序 → 我的 → 管理工作台 → 学期：建立新学期，设置第一周周一、年级（例如 25,26,27）、教学周数和节次等。当前不是任意编辑既有学期的完整配置管理器。
- 工作台 → 课表：选择 JSON/TXT 或粘贴 JSON，解析预览后确认。可随课程导入新增班级；既有班级用原 ID 引用，不能重复声明。当前要求至少一条课程，不能只上传班级清单。重复课程 ID 拒绝，不是覆盖更新。
- 云端模式确认后会提交内容给服务端再次校验并保存；不再显示旧的“不会上传服务器”提示。
- 还没有独立网页管理后台、通用教务 XLSX 自动识别、纯班级手工维护页面或完整课表版本变更界面。现阶段对技术人员可用，但对部长日常维护还不够方便。
- 后端管理也应经过相同受鉴权命令（createSemester/import）。不建议手工修改 PostgreSQL workspace 的 JSON，否则会绕过校验、审计和并发保护。

## 第二位管理员

当前支持多个 admin 的数据模型，但成员管理只开放 member/leader 切换，不能通过现有界面增加第二位管理员。BOOTSTRAP_OPENID 只在无任何管理员时初始化第一位，改成另一个人的标识不会自动新增管理员。

后续可新增：对方真实微信申请并审核入组 → 现有管理员明确确认“授予管理员” → 服务端检查并记录审计；撤销／交接应保证至少一个有效管理员。小程序业务管理员不需要获得腾讯云密钥或微信公众平台账号。本轮没有实现或执行此授权扩展。

## 彻底重置（新增，试用环境）

入口：我的 → 管理工作台 → 操作记录 → 查看彻底重置范围。与原“试用数据清理”是两个独立功能。

- 删除范围：全部成员和管理员、申请、学期、班级、课程、无课时间、排班／草稿、记录、操作记录、已登记照片，以及 xuedu-photos 桶 trial/ 目录中的未登记照片。清空后保存空白工作区和最少系统元数据，不 DROP 数据库或删除云环境。
- 保留：代码、云环境、连接密钥、BOOTSTRAP_OPENID 指定的本人重新初始化资格。平台备份／日志、设备上的照片／缓存／导出文件、他人保存的副本不由该功能远程清除；成功操作会清掉当前设备对应试用环境的表单缓存。
- 权限：仅当前有效管理员且可信微信匹配 BOOTSTRAP_OPENID 可执行；production 硬性拒绝，不支持完整存储核查的旧后端也拒绝。
- 流程：只读预览、输入“清空全部业务数据”、冻结写入、等待在途上传、每次最多扫描／删除 20 个照片、确认目录为空后清空业务。异常不宣称完成，保持冻结，重新预览并继续即可。未知路径或清单格式异常会停止，而不是冒险删除。
- 当前等待在途上传 10 秒，依据已部署函数最大执行时长 3 秒。将来提高函数超时必须同步调整排空机制，不能只改控制台超时。
- 成功后更换数据轮次，旧客户端写入拒绝；仅允许原指定微信在申请页建立真实空白学期和本人班级，随后本人填写资料重新初始化管理员，不恢复演示课表。正式课表仍需导入。

本轮 58 项测试、类型检查、两套构建及修改页面 WXML 编译通过；真实试用云函数已部署。只读预览与照片目录核查通过，确认弹窗已取消，未调用 resetAllBegin/resetAllStep，未删除真实数据。真实照片删除、失败恢复和重置后的真机初始化仍未破坏性演练。
